# Azure AD App Registration

Terraform module to manage an app registration in Microsoft Entra ID (Azure AD).
It can optionally create the enterprise application (service principal), a client
secret with an explicit expiration date, and federated identity credentials (standard
or flexible) so that external workloads can authenticate without a secret.

## Permissions

The identity running Terraform needs one of the following:

* Microsoft Graph application permission `Application.ReadWrite.All`
  (or `Application.ReadWrite.OwnedBy` when it is an owner of the app registrations it manages).
* Entra ID role `Application Administrator` or `Cloud Application Administrator`.

Creating owners referencing other users or service principals also requires
`Directory.Read.All` (or equivalent) to resolve the object IDs.

## Authentication

The `azuread` provider must be configured by the caller of this module. Supported methods include:

* OpenID Connect / dynamic provider credentials (recommended), for example with HCP Terraform
  using `ARM_USE_OIDC`, `ARM_TENANT_ID` and `ARM_CLIENT_ID`.
* Client secret using `ARM_TENANT_ID`, `ARM_CLIENT_ID` and `ARM_CLIENT_SECRET`.
* Azure CLI (for local development only).

## Features

* Creates the app registration (`azuread_application`).
* Optionally creates the enterprise application (`azuread_service_principal`), enabled by default.
* Optionally generates a client secret (`azuread_application_password`) with a mandatory expiration date.
  The value is generated by Entra ID and exposed through the sensitive `client_secret` output.
* Optionally configures one or more federated identity credentials
  (`azuread_application_federated_identity_credential`), for example for HCP Terraform, GitHub Actions or Kubernetes.
* Optionally configures flexible federated identity credentials
  (`azuread_application_flexible_federated_identity_credential`, preview) that match token claims with
  wildcards, so one credential can cover a whole HCP Terraform project (all workspaces and run phases).
  Only supported for GitHub, GitLab and HCP Terraform issuers.

> **Note:** a generated client secret is stored in the Terraform state. Protect the state
> (for example with HCP Terraform remote state) and prefer federated credentials whenever possible.

## Usage example

### App registration with a federated credential (no secret)

```hcl
module "appregistration" {
  source  = "app.terraform.io/<ORGANIZATION>/appregistration/azuread"
  version = "0.0.0"

  display_name = "app-hcp-terraform"

  federated_credentials = {
    tfc-plan = {
      issuer  = "https://app.terraform.io"
      subject = "organization:my-org:project:my-project:workspace:my-workspace:run_phase:plan"
    }
    tfc-apply = {
      issuer  = "https://app.terraform.io"
      subject = "organization:my-org:project:my-project:workspace:my-workspace:run_phase:apply"
    }
  }
}
```

### App registration with a flexible federated credential for a whole HCP Terraform project

```hcl
module "appregistration" {
  source  = "app.terraform.io/<ORGANIZATION>/appregistration/azuread"
  version = "0.0.0"

  display_name = "app-hcp-terraform-project"

  flexible_federated_credentials = {
    tfc-project = {
      issuer                     = "https://app.terraform.io"
      claims_matching_expression = "claims['sub'] matches 'organization:my-org:project:my-project:workspace:*:run_phase:*'"
    }
  }
}
```

### App registration with a client secret

```hcl
module "appregistration" {
  source  = "app.terraform.io/<ORGANIZATION>/appregistration/azuread"
  version = "0.0.0"

  display_name = "app-with-secret"

  secret = {
    end_date = "2027-12-31T23:59:59Z"
  }
}
```
